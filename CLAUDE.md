# gitops-cd

Capability YAML (`capabilities/`) + team registry (`teams/`) → Go renderer (`gcd`, `platform/cli/internal/capability`) → generated manifests (`rendered/`), promoted by Kargo, synced by Argo CD, all running locally on kind: a hub (Kargo control plane) + one cluster per region with its own Argo CD and Kargo shard (ADR 0015). Every Argo CD runs one root app of ApplicationSets; cluster generator labels pick what each deploys (ADR 0017). Overview and logins: `README.md`. Terms: `GLOSSARY.md`. Decisions: `docs/adr/`.

## Layout
App teams own `capabilities/`; everything platform-owned (renderer, cluster, add-ons, tasks) lives in `platform/`. `teams/`, `rendered/`, `docs/` stay at root (ADR 0010).
- `capabilities/<cap>/{owners.yml,stages,targets,apps}`: YAML only; folder name = capability name. Target = dir `targets/<t>/target.yml` (name `<region>-<environmentType>-<k8s|tf|cr>[-<qualifier>]`, lint-enforced, ADR 0025; required `environmentType: dev|npr|prd`, `environment` free name; `platform: K8S` default; `TERRAFORM` for terraform apps: `module:` instead of `image:`, flat `gcpProject`/`region`/`backend`, render `terraform.yaml`, gha only, ADR 0021; `CLOUD_RUN` for image apps, flat `gcpProject`/`region`, render Knative `service.yaml`, gha only, ADR 0024) + optional `environment-variables/<name>.yml` (flat env map; apps opt in with `envFrom: [<name>]`, ADR 0014). One `owners.yml` per capability (ADR 0007): `codeOwners`, `promoters: {<stage>: [emails]}`, `viewers`, `breakGlass`, `apps: {<app>: {codeOwners?, promoters?, viewers?}}` overrides (no app owners files).
- `teams/<team>.yml`: githubTeam only (CODEOWNERS); that team or platform approves it. No access rights.
- `owners.yml` (capability; `apps:` overrides, ADR 0007): `codeOwners` (teams → CODEOWNERS), `promoters` (per stage) + `viewers` + `breakGlass` (emails `@example.com` → Kargo/Argo CD access); platform-approved.
- `platform/cli/internal/capability/`: the renderer, plain Go (ADR 0030, no CUE): `config.go` platform-owned config (cluster registry, replica policy, pre-deploy checks per environmentType ADR 0028, `platforms` table = all per-platform differences), `load.go` (`routes`: the one file-layout table), `schema.go` + `validate.go` (per-file + cross-file rules → located `Diag`s; reads the YAML as written), `model.go` (layered merge → deploys, owners; derived checks), `graph.go` (pipeline, Kargo Stage graph ADR 0012, name lengths), `kargo.go` (Warehouse: git + image subscriptions, Manual Freight; target Stages get `spec.shard` = cluster region; promote RBAC), `output.go` (workload files, Argo CD params `rendered/argocd/deploys/<region>/<cap>/` + AppProjects `rendered/argocd/projects/<region>/`, CODEOWNERS fragment), `platformfiles.go` (shared `ClusterPromotionTask`s `rendered/kargo/_promotion-tasks.yaml` ADR 0027, `rendered/infrastructure/regions/`, `mise run regions` config). `internal/emit`: ordered YAML/JSON writer. `internal/{render,lint}`: `gcd render`, `codeowners`, `lint` (parallel; `lint.Changed` maps changed files → scope; `internal/progress` bars on a terminal only); test-only `yamledit`, `appsets`.
- `platform/render/`: `testdata/` fixtures + golden, `rendered-README.md`. No editor schemas: lint is the only validation (ADR 0030).
- `rendered/`: generated; CI commits it to the orphan branch `rendered` on each push to main (ADR 0002), gitignored on main (`gcd render` writes it locally). Argo CD + Kargo read branch `rendered`. Never edit. `platform/bootstrap/root.yaml`: root app, identical in every Argo CD, syncing `platform/appsets/`.
- `platform/appsets/`: ApplicationSets (ADR 0017). Cluster labels `example.com/role: hub|region`, `example.com/region: <r>` on each Argo CD's in-cluster Secret. `addons/<addon>.yaml` (git-sourced chart + `$values` / kustomize path; region bits in `valuesObject` via `{{.values.region}}`), `kargo.yaml` (hub `rendered-kargo`), `projects.yaml`, `workloads.yaml`. Static checks: `platform/cli/internal/appsets` tests.
- `platform/cli/`: Go CLI `gcd` (ADR 0018): cluster setup (`up`, `down`, `infra`, `regions`, `certs`, `creds`, `kargo-shards`, `kargo-restore`, `open`, DNS) + the renderer (`render`, `lint`, `codeowners`). Built to `.bin/gcd` by mise task `cli`; the setup mise tasks are one-line `exec .bin/gcd <cmd>`.
- `.github/CODEOWNERS`: generated from `.github/CODEOWNERS.tmpl` + owners; regenerate with `mise run codeowners` and commit it in the PR (CI checks; never hand-edit).
- `platform/infrastructure/<addon>/`: add-on config read from git by its AppSet (`values.yaml`, `manifests/`). `platform/cluster/`: `kind.yaml` (hub), `region.yaml` (region template), `regions` (generated by `mise run regions`; read by up/down/infra).

## Commands (`mise tasks` lists all)
Setup tasks call `.bin/gcd` (`mise run cli` builds it; tasks depend on it). Lint and render have no mise task: run `gcd lint` / `gcd render` (`.bin` is on PATH via mise; rebuild with `mise run cli` after changing `platform/cli`).
- `mise run up` / `down`: fresh hub + region kind clusters + infrastructure + bootstrap / delete everything.
- `mise run open [--print]`: open all UIs (Kargo, hub + regional Argo CD, Keycloak); URL list in `README.md`.
- `mise run infra`: helm-bootstrap Argo CD (hub + regions), apply root app, wait for add-ons in order, git creds, certs, Kargo shard tokens.
- `mise run regions`: regenerate region-derived config from the cluster registry in `capability/config.go` (`platform/cluster/regions`, Keycloak `argocd-<r>` clients, Kargo `api.argocd.urls`); CI checks drift.
- `mise run kargo-restore [cap…]`: after a cluster rebuild, restore each target Stage's current Freight from its `env/*` branch head (idempotent; `docs/operations.md`).
- `gcd lint [cap…] [--changed [--base <rev>]] [--all]` (gcd itself, on PATH via mise; no mise task): full validation → `file:line:col: message`; capabilities in parallel; `--changed` (PR CI) = only what changes since the merge-base can affect (`lint.Changed`); `--all` overrides any narrowing (lint + render). In GitHub Actions with no scope flags, gcd picks scope from the event (PR → `--changed` vs base, label `lint-all` → all; else all) and prints `::error` annotations (`ghactions`).
- `gcd schema [kind] [-s] [--json]`: annotated YAML skeleton per kind (owners, stage, app, target, env-vars): placeholders, required/pattern/description comments; `-s/--sources` adds fixture examples. `gcd show <cap>[/<app>] [--stage s] [--target t] [-s] [--json]`: effective merged config as YAML (owners, `stages.<stage>.<target>`); `-s/--sources` comments each value with its `file:line` (relative to `capabilities/<cap>/`) or default note. `gcd show … --rendered [--include-platform]`: rendered manifests of the selected deploys (+ Argo CD params, Kargo Stage); `--diff [--base <rev>]`: same, changed files as unified diff, unchanged in full. `gcd diff [--base <rev>] [--stat] [--capability c…]`: rendered diff of working tree vs base. `diff`/`show --diff` work with jj or git: base is a jj revset or git rev, default `@-` (jj) / `HEAD` (git); `trunk()` = whole PR. `gcd lint --format text|json|github|auto`. `--color auto|always|never` (all commands; auto: TTY and no `NO_COLOR`; `--json` never colored). `--root`: `show|lint|render` take a config root (sandbox: `platform/render/testdata/root`); `schema`/`diff`/`show --diff` take a repo root (jj or git).
- `gcd render [out] [--capability c…] [--platform] [--all]`: render all capabilities + regenerate CODEOWNERS.
- `mise run test` = `test-cli` (gofmt + `go vet` + `go test ./...` in `platform/cli`: renderer golden, CODEOWNERS, lint cases, render assertions; `UPDATE=1` accepts golden) + `test-tf` (`platform/tests/tf-module-push.sh`).
- CI, one workflow per component: `config.yaml` (every PR/main push: build gcd, lint, CODEOWNERS, render, diff comment, push branch `rendered`), `cli.yaml` (only on `platform/cli`, renderer fixtures, appsets/bootstrap/infrastructure/cluster, `.mise.toml` changes: `test-cli` + regions drift), `tf-module.yaml` (tf-module-push script/example). Shared setup: `.github/actions/setup-go`. A new test reading another path: add it to `cli.yaml` `paths`.

## Rules
- **Fully local and reproducible**: `mise run up` must go from nothing to working with no manual steps (after the repo is pushed: `rendered/` syncs from GitHub branch `rendered`). After changing cluster, infrastructure or auth, prove it with a clean `mise run up`; `mise run infra` alone doesn't catch bootstrap-order bugs.
- **GitOps-only**: no UI user gets create/edit/delete rights in Kargo or Argo CD. All UI access is generated per capability from `owners.yml` emails, matched on the OIDC `email` claim; never IdP groups/roles (ADR 0011): Kargo project per app `kargo-<cap>-<app>` (ADR 0029) with `promote-<stage>` (that stage's promoters) + `viewers` (read project) and `users-<cap>` global SAs (list projects), Argo CD AppProject `viewer-<app>` roles (read-only); no global viewers or global policies. Sole exception: admin emails hardcoded in Kargo + Argo CD values + break-glass guard `ADMIN_EMAILS` (ADR 0009); Kargo edits still blocked by `gitops-only.yaml`.
- **Break-glass (ADR 0013, `docs/break-glass.md`)**: Kargo checks `promote` for approving unverified Freight too, so the approve endpoint goes through a Traefik ForwardAuth guard (`platform/infrastructure/break-glass/`) that allows only the Stage's `example.com/break-glass` emails (from `owners.yml` `breakGlass`) + admins.
- **Pin versions**: tools in `.mise.toml`, charts in `platform/appsets/addons/<addon>.yaml` `targetRevision`, infra images by tag or digest. App images: `app.yml` `image` is a repo only; Kargo discovers SemVer tags and Freight pins the digest (ADR 0016).
- **Idempotent tasks**: every command in `platform/cli` (and any remaining `platform/mise-tasks/*` script) must be safe to re-run. `go vet` + `go test` in `platform/cli` run in `mise run test` and CI (`cli.yaml`).
- **Secrets** come from fnox (`.fnox.toml`, macOS keychain); `mise run creds` puts GitHub App creds + the GHA dispatch PAT (`github-actions`, ADR 0020) in `kargo-shared-resources` (Argo CD needs none: public repo). Nothing secret in git.
- Teams write only YAML (ADR 0006). Every option is a YAML field: add it to the schema in `capability/schema.go` (or `validate.go` for targets/owners), read it in `model.go`. User-facing validation messages are the `Diag` strings in `validate.go` / `model.go`.
- Output field order is whatever the Go builders write (`emit.M(...)` is ordered); the golden test guards it.
- **VCS is jj.** No git mutations, no pushes.

## Changing infrastructure
- Manual runbooks (break-glass, resetting Kargo state): `docs/operations.md`.
- What Argo CD pulls from git vs what needs `mise run infra` / `up`: `docs/sync-boundaries.md`. Add-ons are git-sourced from `main` (ADR 0017): **push** before they take effect.
- Edit `platform/infrastructure/<addon>/` or `platform/appsets/`, push to `main`; Argo CD syncs it. `mise run infra` only bootstraps/waits.
- **New addon**: `platform/infrastructure/<addon>/` (values/manifests) + `platform/appsets/addons/<addon>.yaml` (copy one with the same cluster selector), and add it to the hub wait list in `infra.HubWaitRest` (`platform/cli/internal/infra`) if hub-side. All add-ons start together: dependencies (CRDs, webhooks, OIDC issuer) are absorbed by unlimited sync retries; only host steps wait on specific apps.
- **Regional addons** (`argocd-region`, `kargo-shard`): cluster gen selecting `example.com/role: region`, region bits in `valuesObject` with `{{.values.region}}`. Hub side per region (`kargo-shard-hub`, `argocd-region-hub`): matrix hub × `rendered/infrastructure/regions/*.json` (`{{.region}}`). The hub never gets region credentials (ADR 0015).
- **New region**: add a cluster in `platform/cli/internal/capability/config.go`, `mise run regions`, merge (CI renders), then a clean `mise run up`.
- **Expose a UI**: Traefik `IngressRoute`, not `Ingress`.
- **New OIDC client**: add it to `platform/infrastructure/keycloak/manifests/kargo-realm.json` as a public client with `pkce.code.challenge.method: S256` (it gets the `email` claim by default; don't add group mappers).
