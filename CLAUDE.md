# gitops-cd

Capability YAML (`capabilities/`) + team registry (`teams/`) → CUE renderer (`platform/render/`) → generated manifests (`rendered/`), promoted by Kargo, synced by Argo CD, all running locally on kind: a hub (Kargo control plane) + one cluster per region with its own Argo CD and Kargo shard (ADR 0015). Overview and logins: `README.md`. Terms: `GLOSSARY.md`. Decisions: `docs/adr/`.

## Layout
App teams own `capabilities/`; everything platform-owned (renderer, cluster, add-ons, tasks) lives in `platform/`. `teams/`, `rendered/`, `docs/` stay at root (ADR 0010).
- `capabilities/<cap>/{owners.yml,stages,targets,apps}`: YAML only; folder name = capability name. Target = dir `targets/<t>/target.yml` + optional `environment-variables/<name>.yml` (flat env map; apps opt in with `envFrom: [<name>]`, ADR 0014). App owners: `apps/<app>/owners.yml` else capability `owners.yml`.
- `teams/<team>.yml`: githubTeam only (CODEOWNERS); that team or platform approves it. No access rights.
- `owners.yml` (capability, optional per-app field replace): `owners` (teams → CODEOWNERS), `promoters` + `viewers` (emails `@example.com` → Kargo/Argo CD access); platform-approved.
- `platform/render/`: CUE package `render` (module root `platform/cue.mod/`): `input` path routing, `clusters` registry, `team` stages/targets + prod autoPromote rule, `owners`, `app` layered merge, `pipeline`, `k8s`, `delivery` Kargo (Warehouse: git + image subscriptions, Manual Freight; target Stages get `spec.shard` = cluster region)/Argo CD (`rendered/argocd/<region>/`) + promote RBAC + AppProjects, `files` outputs + CODEOWNERS fragment. `schemas/` generated editor schemas (committed), `testdata/` + golden, `scripts/`.
- `rendered/`: generated by CI on main; never edit. `platform/bootstrap/`: hub root app syncing `rendered/kargo`; `region.yaml` template for each region's root app syncing `rendered/argocd/<region>`.
- `.github/CODEOWNERS`: generated from `.github/CODEOWNERS.tmpl` + owners (never edit).
- `platform/infrastructure/<addon>/`: cluster add-ons managed by Argo CD (`app.yaml`, `values.yaml`, `manifests/`). `platform/cluster/`: `kind.yaml` (hub), `region.yaml` (region template), `regions` (one region per line; read by up/down/infra).

## Commands (`mise tasks` lists all)
- `mise run up` / `down`: fresh hub + region kind clusters + infrastructure + bootstrap / delete everything.
- `mise run open [--print]`: open all UIs (Kargo, hub + regional Argo CD, Keycloak); URL list in `README.md`.
- `mise run infra`: (re)apply infrastructure apps in order, git creds, bootstrap. `mise run infra-render [addon…]`: show the inlined Applications.
- `mise run lint [cap…]`: full validation → `file:line:col: message`.
- `mise run render [out]`: render all capabilities + regenerate CODEOWNERS.
- `mise run test`: golden + CODEOWNERS + lint cases (`UPDATE=1` accepts golden).
- `mise run schemas`: regen `platform/render/schemas/` after changing `#App`/`#Stage`/`#Target`/`#EnvironmentVariables`/`#Owners`/`#Team`.

## Rules
- **Fully local and reproducible**: `mise run up` must go from nothing to working with no manual steps (after the repo is pushed: `rendered/` syncs from GitHub `main`). After changing cluster, infrastructure or auth, prove it with a clean `mise run up`; `mise run infra` alone doesn't catch bootstrap-order bugs.
- **GitOps-only**: no UI user gets create/edit/delete rights in Kargo or Argo CD. All UI access is generated per capability from `owners.yml` emails, matched on the OIDC `email` claim; never IdP groups/roles (ADR 0011): Kargo `promote-<app>` (promoters) + `viewers` (read project) and `users-<cap>` global SAs (list projects), Argo CD AppProject `viewer` roles (read-only); no global viewers or global policies. Sole exception: admin emails hardcoded in Kargo + Argo CD values + break-glass guard `ADMIN_EMAILS` (ADR 0009); Kargo edits still blocked by `gitops-only.yaml`.
- **Break-glass (ADR 0013, `docs/break-glass.md`)**: Kargo checks `promote` for approving unverified Freight too, so the approve endpoint goes through a Traefik ForwardAuth guard (`platform/infrastructure/break-glass/`) that allows only the Stage's `example.com/break-glass` emails (from `owners.yml` `breakGlass`) + admins.
- **Pin versions**: tools in `.mise.toml`, charts in `platform/infrastructure/<addon>/app.yaml` `targetRevision`, infra images by tag or digest. App images: `app.yml` `image` is a repo only; Kargo discovers SemVer tags and Freight pins the digest (ADR 0016).
- **Idempotent tasks**: every `platform/mise-tasks/*` script must be safe to re-run.
- **Secrets** come from fnox (`.fnox.toml`, macOS keychain); `mise run creds` puts GitHub App creds in `kargo-shared-resources` (Argo CD needs none: public repo). Nothing secret in git.
- Teams never write CUE (ADR 0006); every option is a YAML field in `#App`/`#Stage`/`#Target`/`#Owners`/`#Team`. User-facing validation messages come from `error("...")` in CUE.
- Watch for field shadowing in CUE (`x: x`); use the `_cap`/`_capStages`/`_capTargets`/`_repoURL` aliases.
- **VCS is jj.** No git mutations, no pushes.

## Changing infrastructure
- Manual runbooks (break-glass, resetting Kargo state): `docs/operations.md`.
- What Argo CD pulls from git vs what needs `mise run infra` / `up`: `docs/sync-boundaries.md`. Infra Applications are inlined from the local checkout, not git-sourced.
- Edit `platform/infrastructure/<addon>/`, then `mise run infra`.
- **New addon**: create `platform/infrastructure/<addon>/` from an existing `app.yaml`, add it to the ordered list in `platform/mise-tasks/infra`. Order matters: CRDs, webhooks and the OIDC issuer before their users; `argocd` last.
- **Regional addons** (`argocd-region`, `kargo-shard`; hub side `kargo-shard-hub`): templated with `__SHARD__` = region, rendered with `SHARD=<r> mise run infra-render <addon>`, applied per region by `infra`/`kargo-shards` with explicit `--context`. The hub never gets region credentials (ADR 0015).
- **New region**: add a line to `platform/cluster/regions` + a cluster in `platform/render/clusters.cue`, then a clean `mise run up`.
- **Expose a UI**: Traefik `IngressRoute`, not `Ingress`.
- **New OIDC client**: add it to `platform/infrastructure/keycloak/manifests/kargo-realm.json` as a public client with `pkce.code.challenge.method: S256` (it gets the `email` claim by default; don't add group mappers).
