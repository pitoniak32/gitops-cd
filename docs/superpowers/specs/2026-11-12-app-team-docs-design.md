# App-team documentation — design

Sub-project 1 of 3 of the docs effort. Readers, in priority order: app teams (this spec), evaluators (sub-project 2: concept/design tour), platform engineers (sub-project 3: architecture, renderer, ops). Each gets its own spec + plan.

## Goal

An app team member can onboard a system, change apps/stages/targets, promote, and fix lint errors from `docs/` alone, without reading Go or asking the platform team. Docs never silently drift: the field reference is generated, and every guide example is linted in CI.

## Decisions

- Plain markdown in `docs/`, read on GitHub. No site generator.
- Layout: hand-written task pages in `docs/guide/` + generated field reference in `docs/reference/`.
- Reference generated from `system.Schemas(cfg)` (same source as `gcd schema`); drift-checked by a Go test.
- `gcd docs` owns all docs work: regenerates `docs/reference/`, then checks every annotated YAML block in `docs/guide/`. `gcd lint` stays systems-only.
- CI: Go tests (drift + snippets) in `cli.yaml`, which also triggers on `docs/guide/**` and `docs/reference/**`.

`docs/README.md`: app teams → `guide/`; evaluators → root `README.md` + `adr/` (until sub-project 2); platform engineers → `operations.md`, `sync-boundaries.md`, `gotchas.md`, `break-glass.md`, `faq.md` (until sub-project 3). Root `README.md` and `CLAUDE.md` link to it.

## Generated reference

- New command `gcd docs [--out <dir>] [--format text|json|github|auto]`: (1) write the reference, default `docs/reference` (relative to `--root`), one file per `SchemaDoc` kind, idempotent, removes nothing else; (2) check guide examples (below), print diags with lint's printer, exit non-zero on any.
- Page format:
  1. `<!-- generated by gcd docs; do not edit -->` + `# <kind>` + file path pattern + kind description.
  2. Field table: `Field | Type | Required | Values | Platforms | Description | Example`. Nested fields flattened to dotted paths with placeholders (`stages.<stage>.targets.<target>.replicas`, `env.<KEY>`, `envFrom[]`). Values = enum joined by `, `, else pattern in backticks, else empty. Example = link to the first fixture use (`Examples` + `WithExamples` in `examples.go`), relative link from `docs/reference/` to `platform/render/testdata/root/...#L<line>`; empty if unused.
- Rendering lives in `internal/system` next to `SchemaYAML` (e.g. `SchemaMarkdown(docs []SchemaDoc) map[string]string`), command wiring in `internal/cmd/docs.go`.
- Drift test (`internal/cmd`): render to temp, compare byte-for-byte to `docs/reference/`; failure message says `run gcd docs`. `UPDATE=1` rewrites, like other goldens.
- Not part of `gcd render`.

## Tested guide examples

Fence info string carries attributes:

- ` ```yaml path=<repo-relative path> ` — full file content. Must lint clean.
- ` ```yaml path=<path> expect="<substring>" ` — lint must report a diag whose message contains the substring (for troubleshooting).
- ` ```yaml fragment ` — partial snippet, not linted. Use only where a full file is noise.
- A `yaml` block with none of these fails the test (forces a decision).
- Non-yaml blocks (`sh`, `text`, `mermaid`) are ignored.

Checked by `gcd docs` (step 2). `gcd lint` is untouched.

- Code: new package `internal/docs` (`Check(root string) ([]lint.Diag, error)`; reference writing can live here too, calling `system.SchemaMarkdown`).
  1. Glob `<root>/docs/guide/*.md`, extract fenced blocks with line numbers.
  2. Per checked snippet: copy `<root>/platform/render/testdata/root` to a temp dir, write snippet to `path` (overwrite or create), derive system from `systems/<sys>/…` (paths under `teams/` → all), run `lint.All` on it. Snippets in parallel.
  3. Diags located in the markdown: `docs/guide/<page>.md:<line>:<col>: <message>` (snippet line offset + diag line), so text/json/github formats and `::error` annotations work. `expect=` mismatch → `expected lint error containing "<s>", got: …`; unannotated yaml block → `yaml block needs path=…, expect=… or fragment`.
- Go test in `internal/docs` runs `Check` on the repo root and expects no diags, so `mise run test` / `cli.yaml` catch guide edits and schema/validation changes that break examples.

Snippets are independent (fresh copy each). The fixture's teams/targets/stages are available for reference, so guides use the fixture's `payments`/`search` names.

Style: task-first; each page opens with one "you want to…" line. No repeated field lists (link `reference/`), no repeated rationale (link the ADR). ~80–200 lines per page. `faq.md` stays as is (topology/architecture content belongs to sub-projects 2/3).

## CI / repo wiring

- `cli.yaml` `paths`: add `docs/reference/**`, `docs/guide/**`.
- `config.yaml`, `gcd lint`, `lint.Changed`: unchanged.
- `CLAUDE.md`: `gcd docs` under Commands (regenerates reference + checks guide examples; run after schema changes or guide edits, commit `docs/reference/`); docs layout line.
- `mise run test` covers both tests (they're in `go test ./...`).
