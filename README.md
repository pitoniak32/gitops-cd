# gitops-cd

Rendered-manifest continuous delivery, end to end on a laptop: teams describe apps in YAML per
**capability**, a CUE renderer validates and renders Kubernetes manifests plus Kargo/Argo CD
config, and a local kind cluster runs Argo CD + [Kargo](https://kargo.io) to promote them.

## Quickstart

```sh
mise install   # pinned tools (kind, helm, kubectl, cue, jq, yq, fnox)
# first time:
#   - push this repo to github.com/pitoniak32/gitops-cd (rendered/ syncs from main)
#   - a GitHub App installed on that repo with Contents read/write (Kargo pushes
#     env/<cap>/<app>/<stage> branches); store it for fnox:
#     fnox set GITHUB_APP_ID / GITHUB_APP_INSTALLATION_ID / GITHUB_APP_PRIVATE_KEY
mise run up    # tear down + fresh cluster + infrastructure + bootstrap (~5 min)
mise run down  # delete everything
```

| URL | Login |
|---|---|
| https://kargo.localhost | Keycloak user |
| https://argocd.localhost | "Log in via Keycloak" (no local accounts) |
| http://keycloak.localhost | console: `admin` / `admin` |

HTTPS uses a local mkcert CA (`mise run certs`, run by `infra`); the first run asks for your macOS password to trust it.

Users (password = username):

| User | Group | Kargo | Argo CD |
|---|---|---|---|
| `doug` | `team1` | view `kargo-payments`; promote/approve its apps | view `payments` apps |
| `alice` | `team2` | view `kargo-search`; promote/approve its apps | view `search` apps |
| `bob` | none | nothing | nothing |

Nobody can create, edit or delete resources through the Kargo or Argo CD UIs; changes go through git.
Users see only the capabilities their team owns: in Argo CD their apps (read-only, generated AppProject
`viewer` roles; syncing is done by Kargo), in Kargo their projects (generated `owner-<team>` roles).
Kargo's project list still shows other projects' names (listing needs cluster-scoped read); use the
"My projects" filter. Infrastructure apps aren't visible in the Argo CD UI (use kubectl).

## Layout

```
capabilities/<cap>/           one business capability (YAML only)
  owners.yml                  teams owning the capability's apps (platform-approved)
  stages/<stage>.yml          promotion graph: dependsOn, autoPromote
  targets/<target>.yml        cluster / namespace / identity, reused by apps
  apps/<app>/app.yml          image, replicas, env, resources, per stage → target
  apps/<app>/owners.yml       optional: replaces the capability's owners for this app
teams/<team>.yml              githubTeam, idpGroup (platform-owned)
render/                       CUE renderer (package `render`; module in cue.mod/), schemas, tests
rendered/                     generated by CI on main; never edit by hand
  apps/<cap>/<app>/<stage>/<target>/manifests.yaml
  argocd/<cap>.yaml           AppProject + Applications
  kargo/<cap>.yaml            Project, Warehouses, Stages, promote RBAC
  pipelines/<cap>.json        neutral promotion graph
  codeowners/<cap>            fragments → .github/CODEOWNERS
bootstrap/                    root Applications syncing rendered/{argocd,kargo}
infrastructure/<addon>/       Argo CD-managed cluster add-ons (app.yaml, values.yaml, manifests/)
cluster/kind.yaml             local cluster
mise-tasks/                   up, down, infra, infra-render, creds, render, lint, test, schemas
```

## Editing (any editor, Mac or Windows)

Each YAML file's first line points at `render/schemas/`; editors with yaml-language-server
(VS Code + Red Hat YAML, Zed, nvim, Helix, Sublime LSP-yaml) validate and complete as you type.
See `capabilities/payments/apps/my-app/app.yml` for an example of every field.

## Ownership

| Action | Who |
|---|---|
| Approve changes under `apps/<app>/` (except `owners.yml`) | the app's owners |
| Approve changes under `stages/`, `targets/` | union of the apps' owners |
| Approve changes to any `owners.yml` or `teams/` | @acme/platform |
| Promote / approve Freight to any stage of an app | the app's owners (Kargo role per team) |

App owners = `apps/<app>/owners.yml` if present, else the capability's `owners.yml`.
Stages that deploy to a `prod` target can't `autoPromote`. `.github/CODEOWNERS` is generated
by CI on main from `.github/CODEOWNERS.tmpl` + owners files; edit those instead.

## Flow

1. PR: CI lints every capability (errors annotated on the changed lines), renders, and comments the `rendered/` diff.
2. Merge: CI commits `rendered/` and `.github/CODEOWNERS` to main (`render: <sha>`).
3. Argo CD (`bootstrap/rendered.yaml`) syncs `rendered/argocd` and `rendered/kargo` from main.
4. Kargo: each app's Warehouse watches `rendered/apps/<cap>/<app>/`; promotion copies a stage's
   folder to branch `env/<cap>/<app>/<stage>`; Argo CD syncs each target from there.

## How the cluster works

- **Cluster**: kind (`cluster/kind.yaml`), host `127.0.0.1`/`::1` ports 80/443 → Traefik. Kubeconfig is project-local (`.kubeconfig`).
- **Infrastructure**: `mise run infra` helm-installs Argo CD once, then applies one Argo CD `Application` per `infrastructure/<addon>/` (values and manifests inlined by `mise run infra-render`) and waits for each to be Synced + Healthy. Argo CD then manages everything, including itself. Finally it applies git creds (`mise run creds`) and `bootstrap/`.
- **Auth**: Keycloak realm in `infrastructure/keycloak/manifests/kargo-realm.json` (users, groups, `kargo` + `argocd` public PKCE clients with a `groups` mapper), re-imported on every Keycloak start.
- **GitOps-only**: no Kargo admin claim mapping; promote rights come from the generated `owner-<team>` roles (`groups` claim). An admission policy (`infrastructure/kargo-config/manifests/gitops-only.yaml`) blocks the Kargo API from creating/editing/deleting anything except Promotions.
- **Secrets on kind**: the `in-cluster` cluster has no secret store, so `secret:` env values are validated but not rendered.

Rendering details and merge rules: `render/README.md`. Decisions: `docs/adr/`. Gotchas: `docs/gotchas.md`.
